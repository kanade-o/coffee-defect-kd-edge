\section{評価指標}
本研究では, モデルの性能を多角的に評価するため, 分類性能指標とエッジデバイス上での実行性能指標の両面から評価を行う.

\subsection{分類性能指標}
分類性能の評価には, 精度(Accuracy), 適合率(Precision), 再現率(Recall), およびF1スコア(F1 score)を用いる.
これらの指標は, 混同行列の要素である真陽性(TP: True Positive), 真陰性(TN: True Negative), 偽陽性(FP: False Positive), 偽陰性(FN: False Negative)に基づいて算出される.

精度は, 全サンプル中で正しく分類されたサンプルの割合を示す指標であり, 以下の式で定義される.
\begin{equation}
\textit{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN}
\end{equation}
精度はモデルの全体的な性能を把握するのに有効であるが, クラス間のデータ数に偏りがある場合には適切な評価指標とならない場合がある.

適合率は, モデルが正(欠点豆)と予測したサンプルのうち実際に正であったサンプルの割合を表し, 以下の式で定義される.
\begin{equation}
\textit{Precision} = \frac{TP}{TP + FP}
\end{equation}
適合率は誤検出の少なさを評価する指標であり, 値が高いほど偽陽性が少ないことを示す.

再現率は, 実際に正(欠点豆)であるサンプルのうちモデルが正しく検出できた割合を示し, 以下の式で定義される.
\begin{equation}
\textit{Recall} = \frac{TP}{TP + FN}
\end{equation}
再現率は見逃しの少なさを評価する指標であり, 値が高いほど偽陰性が少ないことを示す.
本研究では, 欠点豆の見逃しが品質管理上重大な問題となるため, 再現率を特に重視する.

F1スコアは, 適合率と再現率の調和平均として定義され, 以下の式で算出される.
\begin{equation}
\textit{F1 score} = 2 \times \frac{\textit{Precision} \times \textit{Recall}}{\textit{Precision} + \textit{Recall}}
\end{equation}
F1スコアは適合率と再現率の両者のバランスを考慮した総合的な分類性能を評価できる指標であり, どちらか一方の指標が極端に低い場合にはF1スコアも低くなる特性を持つ.

\subsection{エッジデバイス性能指標}
エッジデバイス上での実用性を評価するため, 平均レイテンシ(AVG. latency), CPU使用率(CPU Usage), およびメモリ使用量(Memory Usage)を測定する.

平均レイテンシは, 1枚の画像に対する推論処理に要する平均時間をミリ秒(ms)単位で表した指標である.
本指標は, 100回の連続推論を実行し, その平均値として算出する.
レイテンシが低いほど高速な推論が可能であり, リアルタイム処理の実現可能性を評価する上で最も重要な指標となる.
また, 平均レイテンシの逆数からスループット(FPS: frames per second)を算出することで, 単位時間あたりの処理可能枚数を評価できる.

CPU使用率は, 推論処理中のCPUリソースの占有率をパーセンテージで示す指標である.
本指標は, psutilライブラリを用いて推論実行中のプロセスのCPU使用率を継続的に監視し, その平均値として算出する.
CPU使用率が高い場合, システム全体への負荷が大きく, 他の処理との並行実行が困難となる可能性がある.
エッジデバイスでは複数のアプリケーションが同時に動作することも想定されるため, 低いCPU使用率が望ましい.

メモリ使用量は, 推論プロセスが使用するメモリ量をパーセンテージで表す指標である.
本指標は, psutilライブラリを用いてプロセスの常駐セットサイズ(RSS: Resident Set Size)を測定し, システムの総メモリ量に対する割合として算出する.
Raspberry Pi 5のような限られたメモリ容量を持つエッジデバイスにおいては, メモリ使用量が実装可能性を左右する重要な制約条件となる.
低いメモリ使用量は, 他のシステムプロセスやアプリケーションとの共存を可能にし, システム全体の安定性を向上させる.

\section{教師モデルの比較実験}
教師モデルの学習では, 各モデルの性能を最大限に引き出すため, 2段階の最適化手順を採用した.
まず, 各モデルについて利用可能なGPUメモリ内で実行可能な最大のバッチサイズを探索し設定した.
次に, 自動最適化フレームワークOptunaを用いて, 学習率($1 \times 10^{-5}$から$1 \times 10^{-2}$の範囲)および重み減衰($1 \times 10^{-5}$から$1 \times 10^{-1}$の範囲)について対数スケールでの探索を行い, 効果的な組み合わせを決定した.

学習率スケジューラには, 線形ウォームアップとコサインアニーリングを組み合わせた手法を採用した.
総学習ステップ数の最初の10\%をウォームアップ期間とし, その後コサインスケジュールに従って学習率を減衰させた.
学習エポック数は150に設定した.
最適化手法には全モデルでAdamWを使用した.

\section{知識蒸留の効果検証}
生徒モデルの知識蒸留では, 教師モデルと同様の学習率スケジューラ(ウォームアップ+コサインアニーリング)を使用し, 150エポックの学習を行った.
蒸留時には, 蒸留損失項の重み$\alpha$を0.5, 温度パラメータ$T$を2.0に設定した.

知識蒸留の効果を検証するため, 生徒モデル単独での学習結果と, 各教師モデルから蒸留した場合の性能を比較した.
これにより, CNNベース教師モデルおよびTransformerベース教師モデルからの知識蒸留の有効性を評価した.

\section{エッジデバイスでの性能評価}
学習済みモデルの実用性を評価するため, Raspberry Pi 5上で推論ベンチマークを実施した.
測定にはPython標準ライブラリおよびpsutilパッケージを使用した.

まず, キャッシュおよびランタイム条件を安定させるため, 測定開始前に20回のダミー推論を実行した.
その後, 前述の評価指標に基づき, 推論時間とリソース使用量を測定した.
これにより, エッジデバイス上でのリアルタイム処理の実現可能性を評価した.
